Day 33–35 详细手册：logging + argparse + 本周复盘（每天约 2 小时）

脚本已经能干活了。这三天的课题：让同一份脚本变成可复用的工具——运行过程可追查、IP/用户名不再写死在代码里。

Day 33：logging——脚本自己的日记本
import logging
logging 记的是「脚本跑了什么」，不是设备 syslog，也不需要 SNMP。

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(message)s",
    handlers=[
        logging.FileHandler("backup.log", encoding="utf-8"),   # 落盘
        logging.StreamHandler(),                                # 同时打屏
    ],
)

五个级别背下来：DEBUG → INFO → WARNING → ERROR → CRITICAL。
level=INFO 表示 INFO 及以上才输出——排障时改成 DEBUG 就能看更细的日志，不用加一行代码。
密码、community 这类秘密不要写进 logging.info。

Day 34：argparse——把写死的值改成命令行参数
import argparse

parser = argparse.ArgumentParser(description="网络设备批量采集工具")
parser.add_argument("-H", "--host", required=True, help="设备 IP")
parser.add_argument("-u", "--username", default="admin1", help="登录用户名")
parser.add_argument("-o", "--output", default="采集汇总.txt", help="输出文件名")
args = parser.parse_args()

# 跑法：python day34_argparse.py -H 192.168.30.252 -u admin1 -o R1.txt
# 漏写必填项会打印帮助并退出，不用自己写 if not host。

Day 35：三合一重构——函数 + logging + argparse
骨架（只改入口，collect / save_report 几乎不动）：

    argparse 收参 → logging 初始化 → 调 collect() → save_report() → 汇总打印

对照关系：
- Day 30 的 collect() / save_report()：干活的零件，参数进、return 出
- Day 33 的 logging：把 print("完成") 换成可落盘的运行记录；失败用 logging.error
- Day 34 的 args.host / args.username / args.output：替换 Day 30 里写死的字符串
- 密码仍用 getpass：不进命令行历史、不进日志文件

跑通标志：
python day35_fun_log_arg.py -H 192.168.30.252 -u admin1 -o R1_采集汇总.txt
屏幕和 backup.log 同时出现「开始连接 / 执行命令 / 报告已写入」；采集结果在 -o 指定的文件里。

2.向过去的自己说清楚（本周四件套）
(1)函数：把会重复的动作包成零件，数据靠参数进、靠 return 出，主程序只负责组装。
(2)正则：对着真实回显写模式，从乱文本里抠字段；人眼扫的事交给程序。
(3)logging：脚本运行过程的日记本，同时打屏和落盘；它不连设备、不读设备日志。
(4)argparse：把写死在代码里的 IP/用户名/文件名改成命令行参数，同一份脚本换设备就能跑。

3.验收
(1)logging 五个级别按顺序写出来；生产环境一般开哪个级别？
答:DEBUG → INFO → WARNING → ERROR → CRITICAL；生产一般开 INFO，排障时临时调 DEBUG

(2)工具脚本为什么用 logging 不用 print？（说出三点）
答:自带时间戳（事后能还原时间线）、分级（一键调 verbosity 不用删代码）、可同时落盘+打屏（屏幕看进度，文件留档案）

(3)argparse 里 required=True 和 default=... 的区别？
答:required 不传就报错退出并提示用法；default 不传则用默认值

(4)--help 的帮助信息是谁生成的？
答:argparse 根据 add_argument 的定义自动生成——写参数定义等于白得一份帮助文档

(5)handlers 里同时给 FileHandler 和 StreamHandler 的效果是什么？
答:日志同时写进文件和打印到终端，两不耽误
