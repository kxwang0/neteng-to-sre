**Day 45：实战——模板 + YAML 数据 = 多台设备配置**

写模板文件 `interface.j2`：

```javascript
sysname {{ hostname }}
{% for intf in interfaces %}
interface {{ intf.name }}
 description {{ intf.desc }}
 ip address {{ intf.ip }} {{ intf.mask }}
{% endfor %}
```

写数据文件 `devices.yaml`：

```yaml
- hostname: R1
  interfaces:
    - {name: GE0/0/0, desc: to-cloud, ip: 192.168.x.11, mask: 255.255.255.0}
    - {name: LoopBack0, desc: router-id, ip: 10.0.1.1, mask: 255.255.255.255}
- hostname: R2
  interfaces:
    - {name: GE0/0/0, desc: to-cloud, ip: 192.168.x.12, mask: 255.255.255.0}
```

渲染脚本：

```python
from jinja2 import Template
import yaml

with open("interface.j2") as f:
    template = Template(f.read())
with open("devices.yaml") as f:
    devices = yaml.safe_load(f)        # 必须用 safe_load，见验收题

for dev in devices:
    config = template.render(dev)
    filename = f"{dev['hostname']}_生成配置.txt"
    with open(filename, "w") as f:
        f.write(config)
    print(f"{filename} 已生成")
```

2.验收
(1)`{{ }}` 和 `{% %}` 各干什么？
答:`{{ }}` 输出变量的值；`{% %}` 是控制逻辑（for 循环、if 判断）

(2)"模板 + 数据 = 配置"相比手写配置的三个好处？
答:标准化（同样数据必出同样配置）、批量（改数据不改模板）、可评审（下发前先 diff 生成的配置）

(3)`yaml.safe_load` 为什么必须用 safe？
答:YAML 能构造任意 Python 对象，恶意 yaml 可借此执行代码；safe_load 只解析基本数据类型，把这条路堵死

(4)为什么生成配置和下发配置要分两步？中间该有什么？
答:中间要有人工 review 或自动 diff（与现网配置比对）；生成和下发分开，事故率天差地别

(5)这套"模板渲染"思路在 DevOps 世界里还有哪些亲戚？
答:Ansible 的 template 模块、Helm 的 values+模板、Terraform 的 templatefile——同一个思想，学会一处通一片（第 9–12 周就会见到 Ansible 版）
