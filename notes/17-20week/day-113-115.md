## Day 113：账号与子账号——安全是第一课
### 1. 注册与实名
- 登录 [阿里云官网](https://www.aliyun.com/)，完成 **实名认证**（个人/企业按实际情况）。
- 未实名通常无法稳定购买/使用 ECS。
### 2. 创建 RAM 子用户（不要用主账号 AK 做实验）
路径：**访问控制 RAM** → **身份管理** → **用户** → **创建用户**
建议：
| 项 | 建议值 |
|---|---|
| 登录名称 | 如 `sre-study` |
| 访问方式 | 勾选 **OpenAPI 调用访问**（用于 Terraform/CLI） |
| 控制台访问 | 学习期可选「控制台登录」便于子账号进控制台；OpenAPI 仍用 AK |
创建完成后 **仅一次** 显示：
- **AccessKey ID**
- **AccessKey Secret**（只显示一次，丢失需禁用后重建）
### 3. 授权（学习期最小权限集）
路径：**RAM 用户** → 该用户 → **权限管理** → **添加权限**
手册推荐（学习期）：
- `AliyunECSFullAccess`（ECS 管理）
- `AliyunVPCFullAccess`（VPC/交换机/安全组等网络资源）
说明：
- **不要用主账号 AccessKey** 写进脚本/Terraform——主账号 AK 等价 root 万能钥匙，泄露可能导致 **盗刷、删库、开大量资源**。
- 生产应再收窄为自定义策略；学习期先用系统策略省事。
### 4. AK 存放纪律（与 Python/Ansible vault 同级）
- AK 存 **密码管理器** 或本机加密笔记，**chmod 600** 的配置文件。
- **永不**写入 `neteng-to-sre`、`ansible-lab` 任何文件。
- **永不** `git add` / 截图发群 / 贴到 Cursor 聊天。
- 将来 Terraform 常用环境变量（示例，值不要写进仓库）：
```bash
export ALICLOUD_ACCESS_KEY="RAM用户的AccessKeyId"
export ALICLOUD_SECRET_KEY="RAM用户的AccessKeySecret"
export ALICLOUD_REGION="cn-hangzhou"   # 与 ECS 地域一致
或在 ~/.aliyun/config.json（不提交 git）中配置默认 Profile。

若 AK 曾泄露：RAM 控制台 禁用该 Key → 新建 Key → 检查账单与异常 ECS。

5. 费用告警（包年用户也要开）
路径：费用与成本 → 告警设置（或 用户中心 → 费用中心 内告警相关入口，以控制台为准）

建议至少：

可用额度 / 余额告警（低于阈值短信或邮件）
日消费 / 账单异常 类告警（若有）
包年 99 元已付主费用，仍可能产生 公网流量、超额磁盘、快照、第二台按量实例 等附加费用；告警用于防误操作。

2.验收
(1)为什么不⽤主账号 AccessKey？
答:主账号 AK 拥有账号全部权限，泄露=整个账号的资源任⼈开矿机盗刷；⼦账号可按最⼩权限授权、泄露可单独禁⽤

(2)按量付费和包年包⽉，学习期选哪个？为什么？
答:按量付费：学习资源随开随销，包⽉再便宜也是整⽉计费—— destroy 纪律 + 按量 = ⼀个⽉⼏块钱

(3)VPC / vSwitch / 安全组，⽤⽹⼯语⾔各是什么？
答:VPC=私有隔离⽹络（⾃⼰的地址空间）；vSwitch=VPC 内的⼦⽹；安全组=作⽤于实例的分布式访问控制列表

(4)AK 泄进 git 后的标准处置流程？
答:⽴即在 RAM 控制台禁⽤并重建该 AK → 从 git 历史中清除（filter-repo）→ 检查账单有⽆异常消费——密钥轮换永远是第⼀步

(5)消费告警为什么第⼀天就要设？
答:⼈总会忘事：告警是唯⼀不依赖记忆⼒的保险；等账单短信来了再找资源，钱已经烧了
