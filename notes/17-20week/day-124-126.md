### 命令（在 Terraform 目录执行）
```bash

# 若无 ECS：terraform apply -var "ecs_password=..."

认知

terraform output -raw：纯值，给脚本 / inventory 用（无多余换行）。
这就是 Terraform 与 Ansible 的数据接口；IP 变就必须 重写 ini（destroy/apply 后不能沿用旧 IP）。

REMOTE HOST IDENTIFICATION HAS CHANGED：不是私钥没删，是 ~/.ssh/known_hosts 里该 IP 对应旧 ECS 指纹 → ssh-keygen -R <IP> 后再连。

Day 125：初始化 playbook
文件
Playbook：~/code/ansible-lab/init_cloud.yaml
Inventory：~/code/ansible-lab/cloud_hosts.ini（[cloud] 组）
playbook 要点（Rocky / dnf）
装 epel-release、htop / vim / curl
用户 netops，groups: wheel（sudo）
netops_password：vars 里 {{ netops_password | mandatory }}，禁止写进 yaml default / git
password_hash('sha512') + update_password: on_create
PermitRootLogin no + PasswordAuthentication yes（实验环境）
notify: restart sshd → handler 仅在配置变更时重启 sshd（幂等）
控制节点若无 passlib：sudo dnf install -y python3-passlib

第一次运行（必须用 root inventory + 两个密码概念）
cd ~/code/ansible-lab
ansible-playbook -i cloud_hosts.ini init_cloud.yaml -k \
  -e "netops_password=给netops设的强密码"
参数	含义
-k
SSH 密码（首次为 root 的 ecs_password）
-e netops_password=...
写入云主机 netops 的登录密码
关 root 之后：inventory 改为 netops
[cloud]
node1 ansible_host=<IP> ansible_user=netops
后续 playbook：

ansible-playbook -i cloud_hosts.ini init_cloud.yaml -k \
  -e "netops_password=..."
（-k 为 netops 密码；become: true 仍可用 sudo。）

Handler 认知
Task changed 且 notify: restart sshd → 末尾 handler 执行一次。
再跑 playbook 若 sshd 配置 ok → handler 不跑 — 幂等的又一具象。
Day 125 完成标志：playbook 成功；ssh netops@IP 成功；grep PermitRootLogin /etc/ssh/sshd_config 为 no。

踩坑：先关 root、未设 netops 密码（本机实录）
现象
第一次 playbook 未带 -e netops_password（或旧版 yaml 无设密 task），却执行了 PermitRootLogin no。
root SSH：Permission denied（预期）。
netops SSH：无密码 → Permission denied。
Ansible 仍连 root → UNREACHABLE。
恢复（任选）
方式	操作
Workbench
ECS 控制台 → 远程连接 → root + ecs_password → passwd netops；必要时临时 PermitRootLogin yes 再 restart sshd
重置密码
控制台重置 netops（或实例密码策略允许时）→ 再 SSH
Terraform 重建
terraform apply -replace="alicloud_instance.node1" -var "ecs_password=..." → 重写 ini → 带 -e 完整 playbook
纪律（写进肌肉）
顺序：创建 netops → 设密码（-e） → 自测 netops 登录 → 再关 root。
mandatory 变量：缺 -e 应 直接失败，避免 silent 锁机。

2.验收
(1)`terraform output -raw` 的 `-raw` 解决什么？
答:默认输出带引号的 HCL 值，-raw 输出纯文本——能直接拼进 inventory/变量，给脚本消费

(2)handler + notify 机制的意义？
答:配置真变化（changed）才触发重启类操作；没变化不打扰服务——避免无谓重启，幂等性的延伸

(3)"禁止 root SSH"为什么算安全基线第一条？
答:root 是全网扫描器爆破的第一目标用户名；禁掉后攻击面砍半（配合密钥登录更佳）

(4)全流程（apply→init→验证）你跑出了多少分钟？瓶颈在哪一步？
答:如实记录；常见瓶颈在 ECS 创建和 dnf 下载——知道瓶颈就知道优化方向（镜像预装、内网源）

(5)这两个工具的分工再总结一遍？
答:Terraform 造资源（壳），Ansible 管状态（装修）；接缝是 output → inventory 的数据传递
