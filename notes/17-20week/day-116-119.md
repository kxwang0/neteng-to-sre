## Day 116：安装 + Provider 认证

**方式 A（手册）**：[developer.hashicorp.com/terraform/install](https://developer.hashicorp.com/terraform/install) 下载 `linux_amd64` zip，`unzip` 后 `sudo mv terraform /usr/local/bin/`。

```bash
sudo yum -y install terraform

```

国内下载 zip 慢时可搜 **阿里云 / 腾讯云 Terraform 镜像**；**Provider 插件**另见下文「§4 Provider 离线安装」。

### 2. 创建 RAM 子用户（Terraform / OpenAPI 用 AK）

> **若 Day 113 已建好子用户并授权**：跳过 §2.1–2.3 的创建与授权，只做 **创建 AccessKey**（若还没有）并核对权限；本节作为 Day 116 完整清单保留。

#### 2.1 控制台路径

1. 使用 **主账号** 登录 [阿里云控制台](https://home.console.aliyun.com/)。
2. 进入 **访问控制 RAM**（Resource Access Management）。
3. **身份管理** → **用户** → **创建用户**。

#### 2.2 创建用户时怎么选

| 项 | Terraform 学习期建议 | 说明 |
|---|---|---|
| **登录名称** | 如 `sre-study`、`kxwang` | 便于审计，与 AK 无直接关系 |
| **访问方式** | 勾选 **OpenAPI 调用访问** | Terraform 必须走 OpenAPI + AccessKey |
| **控制台访问** | **可不勾** | 纯 CLI/Terraform 用户不必给控制台密码 |
| **主账号 MFA** | 建议开启 | 降低主账号被盗风险 |

创建时若勾选 OpenAPI，页面 **仅一次** 展示 **AccessKey ID** 与 **AccessKey Secret**——立刻保存到密码管理器；Secret 关闭后 **无法再看**，只能禁用旧 Key 后新建。

后续补 Key：**RAM → 用户 → 认证管理 → AccessKey → 创建**（每用户通常最多 **2 对** Active Key）。

#### 2.3 授权（权限管理）

路径：**RAM → 用户 → 权限管理 → 添加权限** → **系统策略**：

| 策略 | 用途（Day 116–118 最小集） |
|---|---|
| `AliyunVPCFullAccess` | 创建/删除 VPC 等网络资源 |
| `AliyunECSFullAccess` | 后续管理 ECS；学习期常与 VPC 一并授权 |

- **禁止** 使用 **主账号 AccessKey** 跑 Terraform——泄露风险等同整账号 root。
- 学习期用系统策略省事；生产应改为 **自定义策略**（最小 API + 资源范围）。
- 授权后若 plan 仍报无权限：确认策略挂在 **该用户**、等待 1～2 分钟生效。

#### 2.4 与 Terraform 相关的注意点

| 话题 | 说明 |
|---|---|
| **环境变量** | `ALICLOUD_ACCESS_KEY`、`ALICLOUD_SECRET_KEY`、`ALICLOUD_REGION` 与 `main.tf` 中 `region` 一致 |
| **不要写进 HCL** | `provider "alicloud"` 中不写 `access_key` / `secret_key` |
| **`.bashrc`** | 可长期 `export`，**不提交 git** |
| **RAM API IP 白名单** | 若启用，须加入 **Rocky 访问阿里云时的公网出口 IP**；否则 **plan/apply 403**（与 init/GitHub 无关） |
| **ECS 安全组** | 管 **SSH 进 ECS**，不决定 Terraform 调 VPC API |
| **泄露处置** | RAM 禁用 Key → 新建 → 查账单与异常资源；误提交 git 需轮换 Key 并清理历史 |
| **终端 / 聊天** | 勿贴 Secret；曾泄露建议 **轮换 Key** |

#### 2.5 与 Day 113 的关系

Day 113：**账号安全 + 费用告警 + RAM 总览**。Day 116：**同一套 AK 纪律**，明确专供 **Terraform 进程** 通过环境变量读取。

### 3. AK 认证（不落任何 `.tf` / 不进 git）

Provider 自动读取环境变量：

```bash
export ALICLOUD_ACCESS_KEY="RAM 子用户的 AccessKeyId"
export ALICLOUD_SECRET_KEY="RAM 子用户的 AccessKeySecret"

```

长期生效：三行追加到 **`~/.bashrc`**，执行 `source ~/.bashrc`。**`.bashrc` 不提交 git**。

### 4. Provider 离线安装（Rocky 访问 GitHub 失败时）

**现象**：`curl -I https://github.com` 拒绝连接或超时；`terraform init` 下载 `alicloud` 或拉取 `SHA256SUMS` 失败。

**步骤**：

1. 在浏览器下载（版本与 init 解析一致，如 **v1.293.0**）：  
   `terraform-provider-alicloud_1.293.0_linux_amd64.zip`  
   （Release 页：`aliyun/terraform-provider-alicloud`）

2. 拷到 Rocky，**解压二进制**（镜像目录里放可执行文件，**不是 zip**）：

```bash
cd ~/terraform-mirror/registry.terraform.io/aliyun/alicloud/1.293.0/linux_amd64
unzip -o terraform-provider-alicloud_1.293.0_linux_amd64.zip
chmod +x terraform-provider-alicloud_v1.293.0
# 可选：rm -f *.zip
```

3. 配置 **`~/.terraformrc`**：

```hcl
provider_installation {
  filesystem_mirror {
    path    = "/home/kxwang/terraform-mirror"
    include = ["registry.terraform.io/aliyun/alicloud"]
  }
  direct {
    exclude = ["registry.terraform.io/aliyun/alicloud"]
  }
}
```

4. 工程目录：

```bash
cd ~/code/terraform-lab/day116-vpc
rm -rf .terraform
terraform init
```

init 可能出现 **unauthenticated / Incomplete lock file** 警告——本地镜像 + 仅本机 `linux_amd64` 时可接受。

**说明**：init 连 Registry/GitHub，**不是**阿里云 API；**ECS 安全组**、**RAM IP 白名单** 不解释 GitHub 失败；plan/apply 若 403 再查 RAM 白名单。

**Day 116 完成标志**：`terraform version` 正常；RAM 子用户 + AK + 授权就绪；AK 仅环境变量；`day116-vpc` 下 `terraform init` 成功。

## Day 117：HCL 语法 + 第一个 VPC

工程：`~/code/terraform-lab/day116-vpc/main.tf`

**手册示例（杭州）**：

```hcl
terraform {
  required_providers {
    alicloud = {
      source = "aliyun/alicloud"
    }
  }
}

provider "alicloud" {
  region = "cn-hangzhou"
}

resource "alicloud_vpc" "lab" {
  vpc_name   = "sre-lab"
  cidr_block = "172.16.0.0/12"
}
```

**本机实际（北京 + 锁定 Provider 大版本）**：

```hcl
terraform {
  required_providers {
    alicloud = {
      source  = "aliyun/alicloud"
      version = "~> 1.230"
    }
  }
}

provider "alicloud" {
  region = "cn-beijing"
}

resource "alicloud_vpc" "sre_lab" {
  vpc_name   = "sre-lab"
  cidr_block = "172.16.0.0/16"
}
```

### HCL 认知

- 形式：`resource "类型" "逻辑名" { 参数 }`
- **声明「要什么」**；如何调 API 创建是 **Provider** 的事。
- **声明式**：与 Ansible 相同理念；Terraform 管 **资源是否存在**（造壳），Ansible 管 **机器内部状态**（装修）。

| 手册 | 本机实践 |
|---|---|
| zip 安装 Terraform | yum 安装 v1.16.4 |
| `cn-hangzhou` | `cn-beijing` |
| `172.16.0.0/12` | `172.16.0.0/16` |
| 在线 `init` | `terraform-mirror` + `~/.terraformrc` |

**Day 117 完成标志**：`main.tf` 就绪；可选 `terraform validate`；理解 resource 与 provider 分工。

## Day 118：工作流四部曲（刻进肌肉）

```bash
cd ~/code/terraform-lab/day116-vpc

terraform init      # 初始化：安装 provider（新目录第一次必跑；改 provider 声明也要再 init）
terraform plan      # 预演：将创建/修改/销毁什么——唯一不改真实资源
terraform apply     # 执行：落地 plan，输入 yes
terraform destroy   # 销毁：本 state 管理的资源全部回收，输入 yes
```

### 控制台验证

- 地域与 `region` 一致（如 **华北2 北京**）
- **VPC 列表**：`apply` 后出现 **`sre-lab`**；`destroy` 后消失
- **99 元包年 ECS** 在默认 VPC，**不在** 本目录 state 里——`day116-vpc` 的 **destroy 不会删 ECS**

### 本机实操记录（可选填空）

| 步骤 | 结果 |
|---|---|
| plan | 1 to add `alicloud_vpc.sre_lab` |
| apply | 成功 / VPC ID：________ |
| 二次 plan | No changes |
| destroy | Resources: 1 destroyed |

**Day 118 完成标志**：plan → apply → 控制台确认 → destroy；理解二次 plan 的幂等。

## Day 119：state——Terraform 的台账

### 文件

- **`terraform.tfstate`**（及 `terraform.tfstate.backup`）：记录 **Terraform 管理的云上资源及 ID**
- 与 **`main.tf`（期望）** + **阿里云 API（真实）** 一起用于 `plan` 对账

### 认知三点

1. **账本**：apply 后 state 写入 VPC ID；下次 plan 知「已有 sre-lab」，不重复创建。
2. **丢 state → 孤儿**：云上可能仍计费，Terraform 失去映射；`destroy` 删不到，可能再 apply 又建一套。处置：控制台手工删，或进阶 `terraform import`。
3. **敏感信息**：state 为 JSON → **`.gitignore` 必须含 `*.tfstate*`**；可提交 `main.tf`、`.terraform.lock.hcl`；**不提交** `.terraform/`。

### git 建议（`terraform-lab`）

```gitignore
.terraform/
*.tfstate
*.tfstate.*
```

**Day 119 完成标志**：能解释 state / 孤儿；仓库无 tfstate；知 destroy 依赖 state。

## 2. 验收

**(1) 工作流四部曲各干什么？哪一步是唯一不改资源的？**
答：**init** 初始化并安装 Provider；**plan** 预演（只读）；**apply** 落地；**destroy** 回收本目录管理的资源。**plan** 是唯一不修改云上资源的一步。

**(2) AK 为什么用环境变量而不是写进 provider 块？**
答：写进 `.tf` 易随 **git 泄露**；环境变量不落仓库。长期用 `~/.bashrc`（不进 git）——与 Day 113 / Ansible vault 同一条纪律。

**(3) tfstate 是什么？丢了会怎样？**
答：Terraform **资源台账**（逻辑名 ↔ 云上 ID）。丢失后变 **孤儿**：云上仍存在/可能计费，Terraform 无法正确 destroy，需控制台清理或 import。

**(4) `init` 什么时候必须跑？**
答：**每个新工程目录第一次**；**新增/变更 `required_providers`**；无 `.terraform` 目录时；改 Provider 版本约束后通常也要再 init。

**(5) Terraform 和 Ansible 都是声明式，管的对象有何不同？**
答：**Terraform** 管基础设施 **生命周期**（VPC/ECS 等「有没有」）；**Ansible** 管已存在主机上的 **配置与软件**。一个 **造壳**，一个 **装修**。

**(6) Terraform 用的 AK 应来自主账号还是 RAM 子用户？OpenAPI 与「控制台登录」分别做什么？**
答：必须 **RAM 子用户**（最小授权、可单独禁用 Key）。**OpenAPI + AccessKey** 给 Terraform/CLI 调 API；**控制台登录** 给人网页操作——纯 Terraform 用户可只开 OpenAPI。
