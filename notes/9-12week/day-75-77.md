2.验收
(1)采集层换 Nornir 重写时，check_config() 要不要动？为什么？
答:不动——引擎只吃配置文本，不关心文本是 Netmiko 还是 Nornir 抓的；这就是分层带来的可替换性

(2)JSON 落盘为什么 `ensure_ascii=False`？
答:否则中文（规则名、建议）会被转义成 `\uXXXX`，文件不可读

(3)为什么要先存 JSON 再生成 HTML，而不是直接生成 HTML？
答:JSON 是机器可读的中间层：HTML 只是它的一种渲染，将来还能喂给 API、Excel、告警系统；直接出 HTML 就把数据锁死在展示层了

(4)多设备扫描时单台失败的正确姿势？
答:try/except 记 logging.error，该设备标记为"扫描失败"单独列出，绝不能中断整批；漏报一台和漏报全部是两回事

(5)画一遍本项目的数据流（四步）。
答:rules.yaml + devices.yaml → 并发采集配置 → 引擎逐条规则判定 → JSON 结构化结果（→ 下周渲染 HTML）
