### Day 64–66 详细手册：FastAPI 入门（每天约 2 小时）

> 到现在你的工具只能命令行跑。这周给它开一扇 HTTP 的门——**这是所有"平台"的起点**。

**Day 64：安装 + 最小服务**

```bash
python3.12 -m pip install fastapi "uvicorn[standard]" -i https://pypi.tuna.tsinghua.edu.cn/simple
```

`main.py`：

```python
from fastapi import FastAPI

app = FastAPI(title="网络自动化平台")

@app.get("/")
def index():
    return {"msg": "网络自动化平台 API 在线"}

@app.get("/devices")
def devices():
    return [{"name": "R1", "ip": "192.168.x.11", "vendor": "huawei"}]
```

启动与测试（两个终端）：

```bash
python3.12 -m uvicorn main:app --reload --host 0.0.0.0 --port 8000
# 另一个终端：
curl 127.0.0.1:8000/devices
```

然后浏览器访问 `http://<Rocky-IP>:8000/docs`——**FastAPI 白送一套可交互的 API 文档页面**（Swagger UI），点几下就能直接调接口。第一次看到时，记住这个感觉：好框架就是到处白送。

**Day 65：路径参数与请求方法**

```python
@app.get("/devices/{name}")
def get_device(name: str):
    return {"name": name, "status": "up"}   # 真实场景去查清单/设备

@app.post("/backup/{name}")
def backup(name: str):
    return {"device": name, "result": "备份完成（示意）"}
```

`{name}` 是路径参数；`@app.post` 对应"提交动作"。在 `/docs` 页面里逐个试——比写十遍 curl 学得快。

**Day 66：串起前后端认知**

概念对齐（网工类比）：FastAPI 写的服务 = 一台"应用层设备"；uvicorn = 让它跑起来的进程管理；`/docs` = 设备自带 Web 网管；curl = 手工 ping/telnet 测试。本周不需要学前端，浏览器和 curl 就是你的前端。

2.验收
(1)uvicorn 和 FastAPI 的分工？
答:FastAPI 定义路由和逻辑（应用），uvicorn 是 ASGI 服务器负责监听端口、收发 HTTP（运载）——应用跑在服务器上

(2)`@app.get` 和 `@app.post` 的区别？
答:get 用于"查询"（无副作用），post 用于"提交动作/创建"（有副作用）——语义分工，乱用不算错但违反 HTTP 约定

(3)路径参数 `{name}` 怎么进到函数里的？
答:路径里的值按名字自动注入同名函数参数，FastAPI 还会按类型注解做校验

(4)`/docs` 页面是谁生成的？为什么值钱？
答:FastAPI 根据路由和类型注解自动生成的 Swagger 文档；值钱在"文档永远和代码同步"，且能直接在页面上调接口联调

(5)服务监听 `0.0.0.0` 和 `127.0.0.1` 的区别？
答:`0.0.0.0` 监听所有网卡（局域网上的 Windows 宿主也能访问）；`127.0.0.1` 只听本机回环（只有 Rocky 自己能访问）——对外提供 API 用前者，纯本机调试可用后者
