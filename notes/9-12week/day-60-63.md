**Day 60–61：Scrapli——更现代的网络 SSH 库**

```bash
python3.12 -m pip install "scrapli[community]" -i https://pypi.tuna.tsinghua.edu.cn/simple
```

```python
from scrapli import Scrapli

dev = {
    "host": "192.168.x.11",
    "auth_username": "netops",
    "auth_password": "密码",
    "auth_strict_key": False,
    "platform": "huawei_vrp",     # 来自 scrapli-community
}
conn = Scrapli(**dev)
conn.open()
resp = conn.send_command("display version")
print(resp.result)
conn.close()
```

认知要点：Scrapli 是 Netmiko 的现代替代品（更快、设计更干净、原生支持异步），华为支持来自 `scrapli-community` 扩展包。和 Netmiko 的关系像"新版驱动"——**先吃透 Netmiko 的你，看它就是换个 API**。

**Day 62–63：本周复盘——框架怎么选**

| 工具 | 角色 | 什么时候用 |
| --- | --- | --- |
| Netmiko | 驱动层（直连设备） | 单点小脚本、学习期 |
| Scrapli | 驱动层（更现代） | 新项目、要异步性能时 |
| Nornir | 框架层（编排多个驱动） | 多设备、多任务的生产级采集 |
| Ansible | 声明式 IaC（第 13 周见） | 配置管理、状态收敛 |

写周记回答一个问题：**Day 50 的项目 v2 如果换成 Nornir 写，哪些代码会消失？**（清单解析、线程池、结果归集——这就是框架的价值坐标。）

2.验收
(1)Scrapli 相对 Netmiko 的两个改进点？
答:性能更好（连接复用、异步支持）、API 设计更现代统一

(2)华为的 Scrapli 支持来自哪个包？
答:`scrapli-community`（社区扩展平台包，装 `scrapli[community]` 时一起来）

(3)"驱动层"和"框架层"的区别？
答:驱动层只管"连上一台设备收发命令"；框架层管清单、并发、结果归集、失败处理——编排多台设备

(4)Nornir 底层靠什么连设备？
答:默认靠 Netmiko 插件（也可换 Scrapli 插件）——框架不亲自连设备，它调度驱动

(5)什么场景下你会放弃框架直接写 Netmiko？
答:一次性的小验证、给同事演示的单点脚本——为三台设备起三个 YAML 是过度工程；判断标准永远是"复杂度是否配得上骨架"
