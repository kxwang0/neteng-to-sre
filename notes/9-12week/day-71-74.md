### Day 71–74 详细手册：规则引擎与检查逻辑（每天约 2 小时）

> 网工场景：等保/内部审计要求"设备必须关 Telnet、SNMP community 不能是 public、必须配 NTP、必须开 SSH"。以前靠人逐台 `display current-configuration` 翻——这周教机器翻。

**Day 71：需求抽象——规则就是数据**

设计 `rules.yaml`（**规则不写死在代码里，这是本项目的核心设计**）：

```yaml
- id: SEC-001
  name: 关闭 Telnet 服务
  type: forbid                      # forbid：命中即违规
  pattern: 'telnet server enable'
  severity: high
  advice: 关闭 Telnet，统一使用 SSH 管理

- id: SEC-002
  name: SNMP community 不得使用默认团体字
  type: forbid
  pattern: 'community\s+(simple\s+|cipher\s+)?(public|private)\b'
  severity: high
  advice: 更换为强团体字，优先升级到 SNMPv3

- id: SEC-003
  name: 必须配置 NTP 时间同步
  type: require                     # require：不命中即违规
  pattern: 'ntp[- ]'
  severity: medium
  advice: 配置 ntp server 指向内网时间源

- id: SEC-004
  name: 必须启用 SSH(Stelnet) 管理
  type: require
  pattern: 'stelnet server enable'
  severity: medium
  advice: 开启 stelnet server 并禁用 Telnet

- id: SEC-005
  name: 必须配置本地 AAA 管理账号
  type: require
  pattern: 'local-user\s+\S+\s+password'
  severity: low
  advice: 建立带 privilege level 的本地管理账号
```

两种规则类型：`forbid`（出现即违规）和 `require`（缺失即违规）。正则用的就是第 5 周的本事。

**Day 72–73：检查引擎**

```python
import re
import yaml

def load_rules(path="rules.yaml"):
    with open(path, encoding="utf-8") as f:
        return yaml.safe_load(f)

def check_config(config_text, rules):
    """对一份配置跑全部规则，返回每条规则的检查结果列表。"""
    results = []
    for rule in rules:
        hit = re.search(rule["pattern"], config_text, re.IGNORECASE)
        if rule["type"] == "forbid":
            passed = not hit        # forbid：没命中才算过
        else:
            passed = bool(hit)      # require：命中才算过
        results.append({**rule, "pass": passed})
    return results
```

先在本地文件上测（把以前备份的 `display current-configuration` 拿来当样本），**别急着连设备**——引擎逻辑用纯文本调通，再进网络层。

2.验收
(1)`forbid` 和 `require` 两种规则类型的判定逻辑各是什么？
答:forbid：正则命中 = 违规（不该出现的出现了）；require：正则不命中 = 违规（该出现的没出现）

(2)规则放 YAML 里而不是写死在代码里，好处是什么？
答:加规则不改代码、规则可被评审和版本管理、规则文件本身就能给审计方看——**策略与机制分离**

(3)为什么先在本地配置样本上调引擎，而不是直接连设备？
答:分层调试：引擎是纯文本处理，本地样本能秒级反复跑；直接连设备，每次调正则都要走一遍 SSH，效率差十倍，问题还分不清在引擎还是在网络

(4)`{**rule, "pass": passed}` 这个写法是什么意思？
答:字典解包合并：把 rule 的所有键原样展开，再加一个 pass 键——检查结果自带规则全部信息（id/级别/建议）

(5)SEC-002 里 `\b` 的作用？`\s+` 呢？
答:`\b` 是单词边界，防止 `public1` 这类误命中；`\s+` 匹配一个或多个空白，兼容 `community  public` 多空格的写法
