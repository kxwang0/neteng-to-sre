**Day 78–79：报告模板**

`report.j2`（结构示意，样式自由发挥，但别花时间在 CSS 上）：

```html
<!DOCTYPE html>
<html lang="zh">
<head><meta charset="utf-8"><title>配置合规检查报告</title>
<style>
  body { font-family: sans-serif; margin: 2em; }
  table { border-collapse: collapse; width: 100%; }
  th, td { border: 1px solid #999; padding: 6px 10px; text-align: left; }
  .pass { color: green; } .fail { color: red; font-weight: bold; }
</style></head>
<body>
<h1>配置合规检查报告</h1>
<p>扫描日期：{{ scan_time }}　设备总数：{{ devices|length }}</p>
{% for dev in devices %}
<h2>{{ dev.name }}（{{ dev.host }}）—— 通过 {{ dev.passed }} / {{ dev.total }}</h2>
<table>
<tr><th>ID</th><th>检查项</th><th>级别</th><th>结果</th><th>整改建议</th></tr>
{% for r in dev.results %}
<tr>
  <td>{{ r.id }}</td><td>{{ r.name }}</td><td>{{ r.severity }}</td>
  <td class="{{ 'pass' if r.pass else 'fail' }}">{{ '通过' if r.pass else '违规' }}</td>
  <td>{{ '' if r.pass else r.advice }}</td>
</tr>
{% endfor %}
</table>
{% endfor %}
</body></html>
```

渲染脚本（读 JSON → 渲染 → 写 HTML）：

```python
import json
from jinja2 import Template

with open("compliance_report.json", encoding="utf-8") as f:
    report = json.load(f)
with open("report.j2", encoding="utf-8") as f:
    template = Template(f.read())

html = template.render(**report)
with open("合规检查报告.html", "w", encoding="utf-8") as f:
    f.write(html)
print("报告已生成：合规检查报告.html")
```

**Day 80–81：闭环与演示**——`scp` 或直接在 FastAPI 里加个 `/report` 路由返回 HTML（选做加分项）；对故意"弄脏"的设备配置跑一次（开个 Telnet、删掉 NTP），看报告是否准确标红。**能证明工具抓得到问题，工具才有价值。**

2.验收
(1)`{{ 'pass' if r.pass else 'fail' }}` 这种写法叫什么？
答:模板内的条件表达式（三元写法），Jinja2 支持 Python 风格的内联判断

(2)为什么报告标题栏要显示"通过 x / y"而不只是列明细？
答:管理者只看汇总数字判断"要不要细查"，明细是给执行者的——报告的读者分层，顶部永远先给结论

(3)演示前为什么要故意把设备配置"弄脏"？
答:验证工具真的抓得到问题：全绿的报告什么也证明不了；能标红才证明检查有效（测试思维：既要正例也要反例）

(4)这个项目里 Jinja2 的角色和第 7 周有何异同？
答:同：都是"模板 + 数据 → 文本产物"；异：第 7 周产物是给设备的配置（错一个字符就出事故），这次产物是给人看的报告——渲染容错度高，可以放开练样式

(5)报告文件为什么要起中文名/带日期？（开放题，说你的理由）
答:参考：报告要进周报/邮件/归档，中文名+日期让接收者不用打开就知道是什么、哪天的——文件名是报告的第一印象
