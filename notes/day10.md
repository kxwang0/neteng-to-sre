任务 1：加日志函数（25 分钟）
在 sys_check.sh 基础上改（先备份：cp sys_check.sh sys_check_v1.sh）。在脚本开头加：
bash
log() {                                       # 日志函数：自动带时间戳
  echo "$(date '+%F %T') $1"
}
把脚本里的 echo 全部换成 log，比如 log "===== 系统巡检报告 ====="。体会：函数把重复代码收编成一处——以后改时间格式只改一行。

任务 2：加磁盘告警判断（35 分钟）
在报告末尾加一段智能判断：
bash
# --- 磁盘告警 ---
usage=$(df / | awk 'NR==2 {print $5}' | tr -d '%')    # 抠出数字：去掉 % 号
if [ "$usage" -gt 80 ]; then
  log "【告警】根分区使用率 ${usage}%，超过阈值 80%！"
else
  log "【正常】根分区使用率 ${usage}%"
fi
逐段拆解 usage=$(...) 这条（全部是老知识）：
df / 看根分区 → awk 'NR==2 {print $5}' 取第 2 行第 5 列（如 35%）→ tr -d '%' 删掉百分号 → 得到纯数字。
模拟告警：把 80 临时改成 1，跑一次看到告警输出，再改回去——亲手触发一次告警比看十遍都有用。

任务 3：cron 定时自动跑（30 分钟）

⚠️ cron 执行环境的 PATH 和你登录的终端不同，所以：脚本路径用绝对路径、脚本内部的命令如果不稳也可以写绝对路径（/usr/bin/df 这种），这是 cron 任务的第二坑（第一坑是 % 转义）。

2.验收:
(1)函数怎么定义、怎么调用？带时间戳的 log 函数怎么写？
答:定义:log(){echo"$(date '+%F %T')$1";};调用:直接写log"内容"。函数把重复代码收编成一处，改格式只改一行。

(2)tr -d '%' 的作用？为什么告警判断前必须去掉 %？
答:tr -d'%'删除百分号。因为-gt是数值比较，35%带着%不是纯数字，比较会直接报错--先清洗成纯数字在比。

(3)cron 里为什么必须用绝对路径？
答:cron的执行环境和你登录的终端不同:PATH极简、工作目录不固定，相对路径和裸命令很可能找不到--所以脚本路径、报告路径全写绝对路径。

(4)0 8 * * * 是什么时间？2>&1 又是什么意思？
答:每天8:00整(分0、时8，日月周均为"每")。2>&1把标准错误(2)重定向到标准输出(1)的去除--错误信息和正常输出一起进日志文件。

(5)数字比较为什么用 -gt 而不是 >？（提示：> 在 shell 里是重定向）
答:>在shell里是输出重定向符号，不是数学大于号；数值比较必须用-gt(大于)、-lt(小于)、-eq(等于)这套专用运算符。
