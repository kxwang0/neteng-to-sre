1.今日学习内容
### Day 99–101：role——playbook 的函数化封装
> playbook 越写越大就要拆。**role = Ansible 的「函数库」**：固定目录 + 可复用任务；**site.yml = 入口**，像 Python 里 `main()` 调多个模块。
**Day 99：生成骨架与目录地图**
```bash
cd ~/code/ansible-lab
mkdir -p roles
ansible-galaxy init roles/device_backup
tree roles/device_backup    # 或 ls -R
```
先记四个目录：
| 目录 | 作用 |
|---|---|
| `tasks/main.yml` | 任务主体（干什么） |
| `defaults/main.yml` | 默认变量，**优先级最低**，最易被覆盖 |
| `templates/` | Jinja2 模板 |
| `handlers/main.yml` | 被 `notify` 触发的后续动作（本周了解即可） |
**Day 100**：把备份 playbook 搬进 `device_backup`；新建 **`site.yml` 放在 ansible-lab 根目录**（与 `ansible.cfg`、`hosts.ini`、`roles/` 同级）。再建 `loopback_config`，在 `site.yml` 里列两个 role，搭积木。
**Day 101**：defaults 里放可调参数（如 `backup_dir`），在 play 层 `vars:` 覆盖。对照 Python：role ≈ 包/模块，`tasks/main.yml` ≈ 主函数，`defaults` ≈ 默认参数。

## Play 与 Role 的分工（必记）
**Play**（`site.yml`）写：`hosts`、`gather_facts`、`roles`（或 `tasks`）。
**Role 的 `tasks/main.yml`** 只写 **任务列表**（以 `- name:` 开头），**不能**再写 `hosts:` / `gather_facts:` / `tasks:`。把整段 `backup.yaml` 原样拷进 role 会报错或行为异常。
类比：
| Ansible | Python |
|---|---|
| `site.yml` | 入口脚本 |
| `roles/device_backup/` | 包 `device_backup` |
| `tasks/main.yml` | 对外主逻辑 |
| `defaults/main.yml` | 函数默认参数 |

## 文件内容（当前能跑通版本）
`site.yml`：
```yaml
---
- name: 设备日常运维
  hosts: huawei
  gather_facts: false
  roles:
    - device_backup
    - loopback_config
  vars:
    backup_dir: /home/kxwang/reports/ce_backup
```
`roles/device_backup/defaults/main.yml`：
```yaml
---
backup_dir: backups
```
`roles/device_backup/tasks/main.yml`：三条 `ce_command` → `file` 建目录 → `copy` 写文件；`dest` 用 `{{ backup_dir }}/{{ inventory_hostname }}_{{ lookup('pipe', 'date +%F') }}.txt`，`delegate_to: localhost`。
`roles/loopback_config/tasks/main.yml`：
```yaml
---
- name: 用模板下发 Loopback 配置
  community.network.ce_config:
    parents: interface LoopBack100
    lines:
      - description {{ loopback_desc }}
      - ip address {{ loopback_ip }} 255.255.255.255
```
变量仍来自 `group_vars` / `host_vars` / vault；role 不负责密码。

## 运行方式
```bash
cd ~/code/ansible-lab
ansible-playbook site.yml --ask-vault-pass
```
不必 `-k`（密码在 vault）。备份会落到 play 里覆盖的目录，实测：
```text
/home/kxwang/reports/ce_backup/R1_2026-09-23.txt
/home/kxwang/reports/ce_backup/R2_2026-09-23.txt
```
两个 role 按 `site.yml` 顺序执行：先 `device_backup`（RECAP 里任务名带 `device_backup :`），再 `loopback_config`（LoopBack 已存在时 `ok changed=0`，幂等）。
改回默认备份目录：删掉 `site.yml` 里的 `vars: backup_dir`，或改 defaults，则文件写到 `ansible-lab/backups/`。

## 踩坑
**(1) `--tags` 后面没跟名字**
```bash
ansible-playbook site.yml --ask-vault-pass --tags   # 错
# error: argument -t/--tags: expected one argument
```
任务里还没打 `tags:` 时，不要加 `--tags`。要看有哪些 tag：`ansible-playbook site.yml --list-tags`。
**(2) role 的 tasks 里写了 Play 外壳**
和早期 `backup.yaml` 里 `copy` 顶格一样，模块/任务不能当 Play 字段。
**(3) site.yml 放错目录**
必须放在 **`~/code/ansible-lab/`** 根，才能自动用 `ansible.cfg`、`hosts.ini`、`roles/`、`group_vars/`。
**(4) DEPRECATION WARNING**
`community.network` 弃用提示可忽略；看 `failed=` 和 `ERROR`。

## Day 101：defaults 与覆盖
- role 内 `defaults/main.yml`：`backup_dir: backups`（最低优先级之一）。
- `site.yml` 的 `vars: backup_dir: /home/kxwang/reports/ce_backup` 覆盖 defaults，**不改 role 文件**就换输出路径。
- 也可用 `roles:` 下 `- role: device_backup` + `vars:`，或命令行 `-e backup_dir=...`（更高）。
周记一句：**同一套 role，换 play 层变量 = 换备份落盘位置；换 host_vars = 换 LoopBack IP——剧本结构不变。**

2.验收
(1)role 里 `tasks/main.yml` 和 `defaults/main.yml` 各管什么？
答:tasks 是执行主体（做什么）；defaults 是默认变量（可被任何上层覆盖的参数）

(2)defaults 优先级最低为什么反而是放参数的好地方？
答:正因为最低，使用者随手就能覆盖——参数要"有默认值能跑、想改随时改"，defaults 就是这个语义

(3)`site.yml` 里列两个 role 的执行顺序？
答:按列出顺序依次执行，先 device_backup 后 loopback_config

(4)role 对应你 Python 世界里的什么概念？
答:role ≈ 一个带标准目录的函数库/类：tasks 是方法，defaults 是带默认值的参数，templates 是内部资源

(5)`ansible-galaxy init` 和 `ansible-galaxy collection install` 的区别？
答:init 是本地生成空骨架（创造）；collection install 是从仓库下载别人写好的模块集合（拿来用）
