### Day 92–94 详细手册：ansible-vault——密码不进仓库（每天约 2 小时）

> 你的 Python 项目靠 getpass 守住了红线；Ansible 的对应方案是 vault——**加密存密文，运行时解密**。

**Day 92：创建与使用**

```bash
mkdir -p group_vars/huawei
ansible-vault create group_vars/huawei/vault.yml
# 编辑器里写：
# ansible_password: 你的设备密码
```

vault 文件存的是 AES 密文，**可以安全提交 GitHub**。运行：

```bash
ansible-playbook backup.yaml --ask-vault-pass
```

Ansible 会自动读取 `group_vars/<组名>/` 下与组同名的变量文件——`ansible_password` 自动注入连接，**命令行不用 -k 了**。

**Day 93：编辑与查看 + .gitignore 纪律**

```bash
ansible-vault view group_vars/huawei/vault.yml     # 查看
ansible-vault edit group_vars/huawei/vault.yml     # 修改
```

纪律：vault 密码本身不进仓库（背下来或放密码管理器）；明文变量文件永远不进 git。提交前 `git status` 养成看一眼的习惯。

**Day 94：变量体系地图**

Ansible 变量有二十多处可定义，先记住常用的四层（优先级从低到高）：`group_vars/组名`（全组通用）→ `host_vars/主机名`（单台特殊）→ playbook 里 `vars:` → 命令行 `-e`（最高，临时覆盖）。练一手：vault 放密码（组级），`host_vars/R1.yml` 放 R1 专属的 `loopback_ip`，playbook 里引用。
## 实验目录（~/code/ansible-lab）
```text
ansible-lab/
├── ansible.cfg
├── hosts.ini                 # 组 [huawei]：R1=192.168.30.252  R2=192.168.30.253
├── vars_demo.yaml            # 只引用 {{ loopback_ip }}，play 里不再赋值
├── group_vars/huawei/
│   ├── vault.yml             # 已加密，ansible_password（全组共用）
│   └── loopback.yml          # 组默认 loopback_ip
└── host_vars/
    └── R1.yml                # 只覆盖 R1
文件名必须是 vars_demo.yaml（点），不要建成 vars_demo_yaml。组变量必须是 loopback.yml，不要写成 loopback,yml（逗号 Ansible 不认）。

各文件内容
group_vars/huawei/vault.yml（ansible-vault edit 维护，磁盘上是密文）：

ansible_password: "设备密码写这里，不要贴进 git/笔记"
group_vars/huawei/loopback.yml：

loopback_ip: 10.255.255.254
host_vars/R1.yml：

loopback_ip: 10.0.0.1
vars_demo.yaml（正确版：剧本只引用）：

- name: 变量四层演示
  hosts: huawei
  gather_facts: false
  tasks:
    - name: 看最终用的是哪一层
      ansible.builtin.debug:
        msg: "{{ inventory_hostname }} 将使用 loopback_ip={{ loopback_ip }}"
日常跑：

cd ~/code/ansible-lab
ansible-playbook vars_demo.yaml --ask-vault-pass
--ask-vault-pass 问的是锁 vault.yml 的密码，不是设备密码。

测试过程（含一次踩坑）
1）错法：play 里又写了 vars:
第一次 vars_demo.yaml 在 play 里加了：

vars:
  loopback_ip: 10.255.255.254
跑完 R1、R2 都是 10.255.255.254。当时以为没加载 host_vars/R1.yml。

原因：四层从低到高是 group_vars → host_vars → play 的 vars: → -e。Play 里再定义一遍会盖掉 host_vars。R1.yml 其实已经合并进去了，只是显示不出来。

核对文件有没有被读到：

ansible-inventory --host R1 --ask-vault-pass | grep loopback
这里能看到 10.0.0.1；play 一跑仍会被 vars: 盖成 10.255.255.254。

手册说「playbook 里引用」= 写 {{ loopback_ip }}，不要在 play 里再给它赋默认值。

2）正法：组默认 + 主机覆盖
删掉 play 的 vars:，组默认放 group_vars/huawei/loopback.yml，R1 专属仍放 host_vars/R1.yml。

ansible-playbook vars_demo.yaml --ask-vault-pass
预期：

R1 → 10.0.0.1（host_vars 盖过 group_vars）
R2 → 10.255.255.254（没有 host_vars/R2.yml，用组默认）
3）-e 最高，临时覆盖
ansible-playbook vars_demo.yaml --ask-vault-pass -e loopback_ip=10.9.9.9
R1、R2 都应变成 10.9.9.9。文件不用改，只影响这一次命令。

和备份剧本的关系
backup.yaml 继续用组级 vault 里的 ansible_password，不必再 -k：

ansible-playbook backup.yaml --ask-vault-pass
密码进 group_vars（加密），单台差异进 host_vars，剧本只 {{ 变量 }}。

2.验收
(1)vault 文件为什么能安全提交公开仓库？
答:内容是 AES 加密后的密文，没有 vault 密码无法还原——密文可以公开，密钥不行

(2)`group_vars/huawei/vault.yml` 这个路径为什么"自动生效"？
答:Ansible 自动加载 `group_vars/<组名>/` 目录下所有变量文件（约定优于配置）——放对位置就生效，不用引用

(3)`--ask-vault-pass` 与 `-k` 各问的是什么密码？
答:`--ask-vault-pass` 问的是解开 vault 密文的密码；`-k` 问的是设备 SSH 密码

(4)常用变量四层按优先级排一下？
答:group_vars → host_vars → playbook vars → 命令行 `-e`（逐级覆盖，-e 最高）

(5)vault 密码本身应该怎么保管？
答:背下来或放密码管理器；绝不和 vault 文件放同一个仓库——锁和钥匙不放同一个抽屉
