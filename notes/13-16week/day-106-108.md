func_demo.go——函数 + 错误处理
package main
import (
    "fmt"
    "strconv"
)
func double(a int) int { return a * 2 }
func main() {
    fmt.Println(double(3))
    _, err := strconv.Atoi("abc")
    if err != nil {
        fmt.Println("出错:", err)
        return
    }
}
strconv.Atoi("abc") 必失败，走 if err != nil。没有异常栈「跳出来」，控制流都在眼前。

Day 108：goroutine 十分钟体验
goroutine_demo.go（仓库已有）：

package main
import (
    "fmt"
    "time"
)
func say(id int) {
    fmt.Printf("worker %d\n", id)
    time.Sleep(100 * time.Millisecond)
}
func main() {
    for i := 1; i <= 5; i++ {
        go say(i) // 前面加 go = 并发开跑
    }
    time.Sleep(time.Second) // 主程序不能立刻退出，否则 goroutine 来不及打印
}
go run goroutine_demo.go
多跑几次，worker 1~5 打印顺序不固定——并发调度正常。

2.验收

(1)go run 和 go build 的区别？
答:go run 编译到临时目录并直接运行（开发用）；go build 产出独立二进制（分发部署用，单文件、少依赖）。

(2)Go 的错误处理和 Python 异常机制的本质差别？
答:Go 的错误是普通返回值，必须显式 if err != nil；没有抛出-捕获的隐式跳转，控制流更啰嗦但更清晰。

(3):= 和 var x int = 1 的区别？
答::= 声明并初始化、类型自动推导（函数内常用）；var 是完整声明形式，可只声明不初始化（零值）。

(4)goroutine 相对 Python 线程池的直观优势？
答:一个 go 关键字即可并发，无需建池；goroutine 轻量，适合大量并发（Python 线程开很多个就吃力）。

(5)为什么云原生工具很多用 Go 写？（说两条）
答:编译成单二进制、部署零依赖；并发原语强，适合网络/调度/容器等高并发基础设施。

(6)goroutine_demo 里为什么要 time.Sleep？
答:main 退出后进程结束，未完成的 goroutine 会被杀掉；Sleep 是入门演示用的等待，生产用 WaitGroup 等。
