### Day 88–91 详细手册：第一个 playbook——备份配置的 Ansible 版（每天约 2 小时）

**Day 88：playbook 语法最小集**

`backup.yaml`：

```yaml
- name: 备份华为设备配置
  hosts: huawei
  gather_facts: false          # 网络设备没有 facts 可采，关掉省时间
  tasks:
    - name: 抓取当前配置
      community.network.ce_command:
        commands:
          - display current-configuration
      register: result          # 把任务输出存进变量 result

    - name: 输出打印到控制节点本地文件
      ansible.builtin.copy:
        content: "{{ result.stdout[0] }}"
        dest: "backups/{{ inventory_hostname }}.txt"
      delegate_to: localhost    # 这一步在 Rocky（控制节点）本地执行
```

跑法：

```bash
ansible-playbook backup.yaml -k
ls backups/
```

语法三个要点：YAML 缩进即结构（两个空格，Tab 是死罪）；`register` 把输出存进变量；`{{ }}` 就是 Jinja2——**第 7 周的技能在这里全复活**。

**Day 89：逐行读懂 + 改造**

- `delegate_to: localhost` 的意义：任务默认在"被管设备"语境执行，存文件这步要拉回控制节点
- `inventory_hostname`：内置变量，清单里的主机名——按设备分文件就靠它
- 改造练习：文件名加日期（`{{ lookup('pipe', 'date +%F') }}`）、一次抓三条命令（`stdout` 变列表，索引对应命令序号）

**Day 90：多台设备 + 失败容忍**

清单里加一台故意填错 IP 的"R2"，跑一次观察：Ansible 默认某台失败继续跑其他台、最后汇总 `failed=1`。**对比你 Day 50 手写的 try/except——框架帮你做好的事又多了一件。**

**Day 91：周复盘**——画 Ansible 架构图：控制节点（Rocky）→ SSH → 被管端；无 agent（被管端零安装）是它对网管场景的杀手锏。

2.验收
(1)`gather_facts: false` 为什么必须写？
答:facts 采集是给 Linux 主机的（收集系统信息），网络设备不支持，开着只会报错或浪费时间

(2)`register` 的作用？`result.stdout` 和 `result.stdout_lines` 的区别？
答:register 把任务输出存进命名变量；stdout 是字符串列表（每条命令一项），stdout_lines 是按行拆开的二维列表——取配置用 `stdout[0]`

(3)`delegate_to: localhost` 解决什么问题？
答:任务默认以被管设备为执行语境；"把配置存成文件"发生在控制节点的磁盘上，必须 delegate 回 localhost

(4)`inventory_hostname` 是哪来的变量？
答:Ansible 内置变量，值=该主机在 inventory 里的名字——不用定义直接用

(5)某台设备任务失败，Ansible 的默认行为是什么？
答:该台标记 failed 并跳过其后续任务，其他主机照常执行，最后 PLAY RECAP 汇总成败——框架级失败容忍
