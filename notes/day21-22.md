Day 21：venv 虚拟环境（极其重要的工程习惯）
bash
python3.12 -m venv ~/venvs/netops          # 创建独立环境（放 ~/venvs 统一管理）
source ~/venvs/netops/bin/activate         # 激活（提示符前出现 (netops)）
which python                               # 已指向 venv 里的解释器
pip install requests                       # 装进 venv，不污染全局
pip freeze > requirements.txt              # 导出依赖清单（交付/换机复现用）
deactivate                                 # 退出
类比理解：venv = 给每个项目一台"独立虚拟机"，依赖互不打架——项目 A 用 requests 2.31、项目 B 用 3.x 也不冲突。铁律：以后每个项目先建 venv。

Day 22：requests 调用公开 API
Python
import requests

r = requests.get("https://wttr.in/Beijing?format=j1&lang=zh", timeout=10)
print("HTTP 状态码:", r.status_code)          # 200 = 成功（HTTP 状态码是你的老本行）
data = r.json()                                # 把 JSON 响应直接转成 Python 字典
current = data["current_condition"][0]
print("北京现在:", current["lang_zh"][0]["value"], current["temp_C"], "℃")
如果 wttr.in 访问不稳，换 https://ip-api.com/json（查自己出口 IP 的归属地）。练习目标：能把任意 JSON 响应按层级取出你要的字段——这是以后调设备 API、云平台 API 的通用动作。

2.验收
(1)venv 解决什么问题？
答:隔离项目依赖：每个项目独立一套库，版本互不冲突，也不污染系统 Python

(2)创建、激活、退出 venv 三条命令？
答:python3.12 -m venv ~/venvs/项目名；source .../bin/activate；deactivate

(3)怎么导出依赖清单？换台机器怎么复现安装？
答:pip freeze > requirements.txt；复现：pip install -r requirements.txt

(4)requests.get() 返回的响应里，.status_code 和 .json() 分别是什么？
答:.status_code 是 HTTP 状态码（200 成功/404 不存在/500 服务端错误）；.json() 把响应体解析成 Python 字典

(5)为什么项目依赖不该装进全局 Python？
答:不同项目可能依赖同一库的不同版本，全局装会互相覆盖打架（"依赖地狱"），且破坏系统 Python 的干净
